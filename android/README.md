# Кадр для Android

Нативний Android-клієнт на Kotlin, Jetpack Compose, офіційному Material 3 Expressive 1.6.0-alpha01 та Media3. Мінімальна версія — Android 8.0 / API 26. Скляні поверхні UIKit не імітуються: плаваючі елементи, форми, кольори, кнопки й фізика руху реалізовані компонентами Material.

## Запуск

Відкрити цю папку в Android Studio. Потрібні JDK 17, Android SDK Platform 37.2 та Build Tools 36.0.0. Локальний шлях SDK задається в `local.properties`, який виключено з Git.

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

На macOS/Linux: `./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`.

APK: `app/build/outputs/apk/debug/app-debug.apk`. Після GitHub Actions завантажити артефакт **Kadr-Android-APK**. Робоча копія для встановлення зберігається у `C:\Kadr\android\build\apk\Kadr-android.apk`.

У CI використовується окремий приватний ключ тестового підпису з секрету `ANDROID_DEBUG_KEYSTORE_B64`. Той самий ключ локально міститься в ігнорованій папці `.signing`. Це дозволяє встановлювати наступні APK поверх попередніх, зберігаючи локальні дані. Код приватного ключа не публікується. Власні збірки без цього ключа отримують звичайний локальний debug-підпис; production-публікація потребуватиме окремого release-підпису.

## Що працює локально

- Гостьовий перегляд, необовʼязковий локальний акаунт, унікальний без урахування регістру @нікнейм, імʼя, фото та опис. Власні акаунти й налаштування ізольовані.
- Вертикальна стрічка, підписки, режим огляду, повноекранний режим, альбоми й колажі, розмитий фон навколо медіа. Декодер створюється тільки для поточного видимого відео й зупиняється при переході у фон.
- Лайки, збереження, опис, коментарі, відповіді, лайки коментарів, закріплення автором, редагування й видалення власних коментарів.
- Нативний профіль «Атмосфера»: велике фото, колір нижньої частини зображення, плаваючі дії, QR-код, редагування, вкладки й рівна сітка статичних превʼю.
- Фото/відеопублікації, переставляння, обкладинка, підписи фото, альбоми й колажі, недеструктивні часові межі відео, приватність, коментарі й прихована кількість лайків. Оригінали медіа копіюються без перекодування; чернетки зберігаються автоматично.
- Пошук користувачів, публікацій і тегів, історія пошуку, підписки, текстові чати після підписки, відповіді, реакції, редагування/видалення, закріплені розмови й чернетки чатів.
- Студія: акценти, знайомство, посилання, закріплені публікації, чернетки, історія й колекції. Налаштування приватності та відтворення, блокування, фільтри, ZIP-копія разом з медіа й відновлення.

Локальні акаунти — режим прототипу, а не автентифікація Google/Apple. Демо-відео спільні з iOS; вони пакуються з `../ios/Media`, разом із авторськими відомостями.

## Спільний API

`LocalRepository` — джерело локального стану. Зміни додаються в сталу чергу `ResourceRecord`. `RemoteApi` реалізує той самий контракт, що й iOS: `/users`, підписки, розмови, `/sync` та оригінали `/assets`. Формат payload — JSON у Base64; дати підтримують Foundation reference date та ISO 8601 з REST. UUID нормалізуються без зміни тексту повідомлень чи описів.

Мережа за замовчуванням вимкнена. Для перевірки потрібні розгорнутий HTTPS API з `../backend`, реальна сесія цього API та користувач із UUID поточного локального акаунта. ID можна скопіювати в **Налаштування → Сервер**. Адміністратор може створити відповідний development-акаунт через `social_server.py --create-user nickname "Name" --user-id UUID`. Токени зберігаються зашифрованими Android Keystore, не входять у резервні копії та не надсилаються за редиректами. Підключення не створює сервер автоматично.

Завантаження оригіналів потокове; повторна синхронізація пропускає файл тієї самої довжини, вже наявний на сервері. Черга очищається лише після успішної відповіді. Нові локальні правки, зроблені під час мережевого запиту, не замінюються застарілим ресурсом із відповіді.

## Межі першої Android-версії

Це перший робочий перенос основних сценаріїв, а не заява про повний паритет усіх 70 пунктів iOS. Наступні етапи: Google/Apple OAuth, голосові й медіаповідомлення, сканер QR, інтерактивне кадрування фото/аватарки, додаткові оформлення профілю, відеофон профілю, системні push-сповіщення, розширені інструменти редактора та інтерактивні predictive-back переходи. Ці можливості не показані як фальшиві діючі кнопки.

Перевірки: JVM-тести контрактів/акаунтів і Android-тести в `app/src/androidTest`. Компіляція не підтверджує плавність на кожному телефоні; перед релізом потрібна перевірка на фізичних Android-пристроях.

У AGP 9.2.1 спостерігалося зависання `BidiSpoofing` у `KotlinUFile.getAllCommentsInFile` (підтверджено дампами потоків). Лише цей аналізатор замінений перевіркою `checkSourceText`, яка відхиляє керівні символи bidi у вихідних файлах; решта lint працює. Системний ефект `Modifier.blur` доступний на Android 12+; на старіших системах розмиття потребує окремого резервного способу.

APK для розробки підписуються постійним приватним ключем із repository secret `ANDROID_DEBUG_KEYSTORE_B64`. Файл `.signing/debug.keystore` не входить у Git. Для Google Play потрібен окремий production-ключ.

## 0.1.1 — оформлення

Material 3 1.6.0-alpha01 (найновіший preview на момент оновлення), AGP 9.4.0 і Gradle 9.6.0. Нативний NavigationBar з його індикатором вибору, круглий зовнішній контейнер, expressive shapes у кнопок по всьому застосунку. Профіль використовує один LazyColumn зі стабільною шириною stickyHeader, трьома колонками медіа та нативними верхніми панелями. Нижня частина фото профілю розмивається також на Android 9.

## 0.1.2 — компактні панелі

Верхні елементи стрічки мають видиму висоту 40 dp у зонах натискання 48 dp; повноекранна дія повернута вліво вгорі. Нижня панель — 68 dp, іконки 28 dp, підписи 10 sp, активна нативна M3 toggle-капсула охоплює іконку й текст. Зовнішні поля капсул — 6 dp. Збирається через assembleDebug; тести для цього оновлення за проханням користувача не запускалися.

## 0.1.3 — стабільні острівці

Нижня панель має постійну висоту 68 dp і незмінну круглу форму активної капсули. Профіль знову має плаваючі верхні острівці з локальною палітрою фото. Меню дій розгортаються з кнопки на її верхній грані зі сталим радіусом 24 dp. Оновлення збирається локально без тестів і встановлюється через USB; GitHub Actions не запускається.

## 0.1.4 — поверх контенту

Профіль не має суцільної верхньої панелі: фото проходить під плаваючими кнопками, заголовок відображається звичайним текстом. Розкриття меню триває 460 мс, зі збереженням непрозорої капсули та її заокруглення. Нижній таб зменшений до 60 dp і використовує палітру фото у вкладці профілю. Кнопки пошуку й повноекранного режиму використовують той самий колір контейнера, що й центральні сегменти. Локальна збірка й USB-оновлення, без тестів та CI.

## 0.1.5 — стабільні анімації

Прибрано підкладку закріплених категорій профілю. Popup-вікно меню має незмінний розмір: анімується лише контур обрізання шару, без щокадрового перепозиціонування вікна й повторного вимірювання тексту. Верхні кнопки мають 40 dp у 48 dp зонах взаємодії. Палітра фото кешується й готується до входу в профіль; відтінки табу змінюються плавно. Пункти профілю та студії використовують окремі нативні Card/ListItem зі своїми округлими межами та проміжками. Локальна компіляція, без тестів і CI.

## 0.1.6 — нативні списки та edge-to-edge

Обгортки Card/ListItem замінені офіційним SegmentedListItem і ListItemDefaults.segmentedShapes/SegmentedGap. Для темної теми явно задані світлі ролі foreground та LocalContentColor; палітра фото затемнюється зі збереженням відтінку. Верхні круглі кнопки збільшені до 44 dp, кнопка Ще в рядку дій має 48 dp як сусідні. Контент профілю прокручується під заголовком, категорії малюються одним плаваючим елементом над прозорим місцем у списку. Студія, налаштування та редактор використовують спільний плаваючий заголовок над повноекранним списком. Прозора системна навігація без примусового contrast scrim, безпечні відступи у вмісті. Локальне assembleDebug, без тестів і GitHub Actions.
